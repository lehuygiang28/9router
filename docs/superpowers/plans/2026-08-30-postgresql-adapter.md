# PostgreSQL Adapter + Usage Read-Path Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in PostgreSQL backend behind `DATABASE_URL` without changing 9router business logic, and stop unbounded usage/details reads that lag the dashboard.

**Architecture:** Keep emitting SQLite SQL from repos. A dialect translator plus `postgresAdapter` run that SQL on Postgres. `driver.js` promisifies every adapter (pg is async) and selects Postgres when `DATABASE_URL` is set. SQLite remains the default. Separate, small patches stop the SSE stream from scanning all of `usageHistory`.

**Tech Stack:** JavaScript ESM, `pg` (optionalDependency), `@electric-sql/pglite` (test-only), existing `src/lib/db` adapter contract, Vitest.

## Global Constraints

- SQLite stays the default; Postgres is opt-in via `DATABASE_URL` only (no `DB_DRIVER` flag).
- Do not silently fall back to SQLite if `DATABASE_URL` is set and Postgres init fails.
- Do not rewrite `schema.js` `TABLES` into Postgres types; the translator owns DDL/DML dialect.
- Do not add an ORM.
- Keep `INTEGER` 0/1 flags and JSON `TEXT` columns so `row.isActive === 1` and `parseJson` keep working.
- CamelCase identifiers must be quoted on Postgres.
- `pg` is `optionalDependencies`; PGlite lives in `tests/package.json`.
- Mechanical `await` on adapter calls is required; sqlite adapter files themselves stay sync/upstream-shaped.
- One gateway replica; no Redis for pending-request memory.
- Vercel is not a gateway host.
- Judge tests against `tests/__baseline__/known-fails.txt`, not a fully green suite.

```js
});
```

### Task 3: Postgres adapter + driver selection

**Files:**
- Create: `src/lib/db/adapters/postgresAdapter.js`
- Modify: `src/lib/db/driver.js` — if `process.env.DATABASE_URL` then `createPostgresAdapter({ connectionString })`, migrate, return; on failure throw (no SQLite fallback).
- Modify: `package.json` optionalDependency `pg`
- Modify: `.env.example` with `DATABASE_URL` and `PG_POOL_MAX`
- Modify: `tests/package.json` add `@electric-sql/pglite`
- Test: `tests/unit/db-postgres-adapter.test.js`

**Interfaces:**
- Produces: `createPostgresAdapter({ connectionString, pool, query })` where `query(sql, params)` is optional (PGlite). Methods match the promisified contract. `driver: "postgres"`, `async: true`.
- Uses `AsyncLocalStorage` so `transaction(fn)` pins one client for nested `run/get/all`.
- Intercepts translator kinds: `pragma_table_info` runs information_schema and returns SQLite-shaped `{cid,name,type,notnull,dflt_value,pk}` rows; `pragma_noop` returns ok; `sqlite_master` lists public tables; `skip_backup` no-ops.
- `pg.types.setTypeParser(20, parseInt)` (int8 COUNT → number).
- Pool: `max` from `PG_POOL_MAX` default 10, `idleTimeoutMillis` 30000, `allowExitOnIdle: true`.
- Missing `pg` when `DATABASE_URL` set: throw `install pg or unset DATABASE_URL`.

PGlite contract test covers: init schema via `runMigrationOnce`, settings upsert, connection CRUD, usage insert + daily `ON CONFLICT`, request-details pagination, camelCase columns, COUNT as number.
